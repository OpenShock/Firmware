Editor-independent build setup for VS Code, CLion and plain CMake

## Release Note
The firmware now builds from any editor or terminal without the VS Code ESP-IDF extension and without sourcing an export script first. The local workflow is documented in `docs/DEVELOPING.md`.

- `scripts/build.py` finds an ESP-IDF registered by the Espressif installer on its own, and `scripts/idfenv.sh` / `scripts/idfenv.bat` export the same environment for a shell or a CLion toolchain
- `CMakePresets.json` has a configure and a build preset per board, generated by `scripts/gen_cmake_presets.py`; `cmake --preset <board>` derives the chip and sdkconfig layers from `boards/<board>.defaults`, so CLion and a bare shell build and stamp a board like the script does. A `default` preset with no board is what `idf.py` picks up, since ESP-IDF 6.1 configures with a preset whenever the file exists
- A tree configured by the script builds from CLion or a bare shell too: compiles are launched through ccache by its absolute path, not a bare `ccache` that only an exported shell resolves
- Every build publishes `build/compile_commands.json` for clangd, so IntelliSense follows the board or variant built last whichever way it was built
- Tracked `.vscode/` tasks call `scripts/build.py` for build, flash, monitor, menuconfig and the test suites; `.clangd` points at the shared compile database
